# Clearing the selected apps — Build 51

The previous editor removed its Save button when the picker had no application tokens. AppModel.save and Monitoring.configure also rejected an empty rule list. Closing the editor therefore discarded the user's attempted clear, leaving the old persisted rules active.

An empty picker result is now committed automatically while leaving the empty editor open. Both picker dismissal and a late selection update trigger the same guarded save; partial selections retain the normal Save changes flow. Empty configuration is persisted with duty disabled and sessions removed, then old usage/rest monitors are stopped outside the shared lock. Late callbacks no longer own any rule. Home reads the saved empty list and shows Select apps.

Existing mandatory breaks still prevent removal. Such a rejected clear shows the existing error and restores the actual saved selection rather than leaving a misleading empty editor. This change does not provide early release or deferred removal of an app on a break.
