# Independent app budgets — November 6, 2026

Requested: multiple selected apps, each counted separately, retaining a simple interface and closer fidelity to approved mockups.

## Implementation

One atomic protection-v3.json stores rules, enabled state and per-rule SessionState records. Migration reads old rules plus session.json into the original rule ID, keeping live monitor identities and rest deadlines; no stop/restart on upgrade. A rule's usage event contains exactly one app token. Callback ownership is resolved against that rule's current monitor; retired/removed monitor events are ignored.

The named ManagedSettings store now shields the union of currently resting rules. Releasing A recomputes the union, retaining B. Each rest has its own release monitor. Retired usage monitors are cleaned at rest expiry; expired release monitors are cleaned at the next threshold, never from their own callback. Max nine apps reserves two of Apple's twenty simultaneous monitoring slots. Registration errors are shown per rule; next-cycle registration failure cannot retain an expired shield.

Editing an unaffected rule preserves other monitor identities, usage counters and deadlines. Removing or editing a resting rule is rejected before mutation. New apps default to 20 minutes use / 15 minutes rest. Existing rest settings and deadlines are preserved. Each row expands inline for 10/20/30 or Custom, no new management page. Selection is individual apps, not category/web budgets. Setup registration runs off the UI thread.

Visual adjustments: warmer ivory (#FBF7ED approximately), saturated yellow (#FFD12B approximately), subtle paper grain, smaller-radius outlined controls, centered button text, no extra comic frame or calm-duck rotation. The actual system shield remains iOS-owned and is not represented as a full custom comic page.
