# 自测：从「我就再刷一会儿」开始

2026-10-16。这里的用户反馈是依据 Qi 已表达的偏好做的设计推演，不是真实访谈，也不声称替 Qi 体验到了某种情绪。

## 测试到底做了什么

- 没有实际打开小红书，也没有读取其账号、推荐流或私信。Mac 的桌面控制工具仍报告锁定；真机签名此前因 Xcode 无账号而失败。
- 用 Xcode 的原生 XCTest Runner 实际启动、点击和滚动自己的 App。共三轮：iPhone 17 Pro / iOS 26.5 的 8 项，iPhone SE / iOS 18.2 的 11 项，功能修正后的 iPhone 17 Pro 的 11 项。全部通过，共 30 次用例执行、11 个不同用例。
- 用生产 `SessionState` 加虚拟时钟和注入的系统用量回调，重放 10 个刷屏场景；另有 30 个状态断言通过。它们证明本地状态逻辑，不证明 Screen Time、快捷指令或系统拦截实际投递成功。
- 强制休息 UI 用 `--rehearsal-rest` 创建内存夹具，明确标记「SIMULATION · NO APPS BLOCKED」。测试不会授权 Screen Time、安装真实限制或覆盖真实会话；Release 不支持这个入口。到期测试只把模拟休息缩为八秒。最后另对预览底部间距做了小幅修正，并重新编译和截图检查，避免文案贴住 Home 指示条。

## 按你的心态走了三轮

| 推演反馈，不是用户原话 | 发现 | 已做的修改或结论 |
| --- | --- | --- |
| 「我知道该停了，别让我再做三道题。」 | 原主按钮进入替代活动，再确认，再离开。打断变成新任务。 | 主按钮直接关闭这段交互；喝水、看窗外等变成可选入口。没有打卡、奖励或自律评分。 |
| 「说保存并连接，怎么又回到首页了？到底开没开？」 | 保存后没有自动进入连接引导。 | 成功保存后，在设置页关闭时进入快捷指令引导；首页继续保留权限／信号缺失提示。真机授权后的完整保存链路仍待验证。 |
| 「我选了喝水，是不是就能继续刷？」 | 必须确认替代活动不能变成解锁通道。 | 实际点击选项、完成、关闭，再进设置；休息中的暂停和改规则仍禁用。 |
| 「倒计时完了，还不让我改？」 | 页面状态只在重新进入时刷新，可能滞后。 | 在休息截止时刷新状态；原生测试等待其到期，确认文案变化及设置按钮恢复。 |
| 「我刷几十秒，切出去，再进来呢？」 | 每次 App Closed 都停掉监控，未满一分钟的用量不断丢失。原重放中 30 次 59 秒访问可以留下零分钟。 | 短切换保留同一系统事件；离开满一分钟后再次打开才替换。累计回调按总量核对，不重复计数；短暂离开期间的延迟回调可接收，过时监控的回调拒收。回归重放在第 21 次访问达到门槛，等待真机确认系统行为。 |
| 「这是拦整个 App？里面的私信也不能看？」 | 之前没有在选 App 时直说。 | 选择界面明确说明整 App 暂停、私信也包括在内。遵循已确认的强硬模式，不另加临时解锁。 |
| 「点了系统里的 Visit the duck，鸭子呢？」 | 返回主 App 可能只看到首页。 | 活跃休息期间回到 App，会为该轮休息呈现一次漫画交互；主动关闭后不会在同一进程内反复弹回。系统按钮的实际跳转仍待真机验证。 |

## 真实操作覆盖

首次安装权限拒绝／模拟器限制、一键退出、选水后显示对应结束语、冷静→烦躁→暴怒→冷静、休息中禁用暂停和改规则、选择替代活动不提前解锁、到期不重启 App 即刷新、设置跳转规则页、两个快捷指令名称、中文完整流程、大字体滚动后退出。

截图由 XCTest 自动保存到 `Design/Testing/Round1`、`Round2`、`Round3`，每轮有 `manifest.json` 记录设备、测试名、时间和附件。完整 xcresult 在 `/tmp/scrollstopper-ui-round{1,2,3}.xcresult`。可用 Xcode Test 重跑；源文件为 `Tests/UI/ScrollStopperUITests.swift`。

## 我仍不满意的地方

1. **实际系统拦截的视觉落差。** 漫画整页是 App 内体验；盖在小红书上的页面由 Apple 的 ShieldConfiguration 限制布局。新鸭脸缩略图已接入，但不能凭模拟器漫画页说实际拦截也一样震撼。必须上真机看。
2. **首次设置仍有门槛。** 两个快捷指令需要手动设置。指引已衔接，但能否让你不烦、一次设成功，仍需要实际设置体验。
3. **核心可靠性还没获得端到端证据。** 尤其是锁屏、来电、切走 59 秒、系统延迟回调和休息释放。不能因为单测和 UI 测试全绿，就宣布小红书已能可靠拦住。
4. **幽默的疲劳问题。** 已有三档情绪和轮换文案，但几轮模拟不等于连续用一周。我的判断是平时少说话、只在该停时出场；是否一周后仍有趣，不能在本次测试中证明。

保留计数器的依据是 Apple 对 [DeviceActivityEvent](https://developer.apple.com/documentation/deviceactivity/deviceactivityevent) 和 [includesPastActivity](https://developer.apple.com/cn/documentation/deviceactivity/deviceactivityevent/includespastactivity) 的定义；这是实现推断，真机验收仍以 `DEVICE-VALIDATION.md` 为准。
